SYNOPSIS
SYNOPSIS
Sentinel-Trace is a web-based intelligent product traceability, compliance monitoring, and network security management system developed to improve the visibility, reliability, and security of product-related information across different stages of an organizational workflow. Traditional product tracking and monitoring processes often depend on manual records, spreadsheets, disconnected systems, and periodic inspections, making it difficult to maintain accurate traceability information, monitor compliance requirements, identify security-related activities, and obtain a centralized view of operational data. These approaches can result in duplicated records, delayed identification of issues, difficulty in tracking product history, inconsistent monitoring, and increased manual effort.
The proposed system provides a centralized digital platform that enables authorized users to manage product information, track product movement and related activities, monitor compliance conditions, identify potential network security issues, and generate useful operational information through a unified interface. The Phase 2 version extends the functionality defined during Phase 1 by moving from the initial system design and specification toward an implemented and integrated application. The updated system combines product traceability, compliance monitoring, network scanning, security monitoring, alert management, activity logging, analytics, and reporting within a common platform.
The application is developed using Python, Flask, React.js, SQLite/MySQL, Nmap, RESTful APIs, JavaScript, HTML, CSS, and related Python libraries. React.js is used to develop the interactive frontend interface, while Flask provides the backend services and REST API required for communication between the frontend and application logic. Python provides the core processing environment for traceability, monitoring, data processing, and security-related operations. SQLite/MySQL is used for structured storage of application information, while SQLAlchemy provides database interaction and management. Nmap is integrated to support network discovery and scanning activities. Axios is used for communication between the frontend and backend services.
The system includes important features such as user authentication, dashboard management, product traceability, product and batch management, supplier information management, compliance monitoring, network scanning, network security monitoring, alert generation, activity logging, data visualization, report generation, and administrative management. These modules provide a structured approach for monitoring both product-related information and security-related activities. The centralized dashboard allows authorized users to obtain an overview of important system information and monitor activities without depending on separate applications or manually maintained records.
The Product Traceability Module maintains information related to products and their associated records throughout the traceability process. Product and batch information can be organized so that users can identify relevant product details, track associated activities, and retrieve information when required. The system maintains traceability information in a structured database, reducing dependence on manual documentation and improving the consistency of product records.
The Compliance Monitoring Module supports the identification and monitoring of compliance-related information associated with products and organizational activities. It provides a centralized method for recording compliance information, identifying conditions that require attention, and presenting relevant information through the system interface. This helps authorized users monitor compliance-related activities more efficiently and provides better visibility into records that may require review.
The Network Scanning and Security Monitoring Modules extend Sentinel-Trace beyond conventional product management by providing network-related monitoring capabilities. Network scanning can be used to identify active devices and available services within the authorized monitoring environment. The collected information can be processed and presented through the application so that users can observe network activity and identify conditions that may require further investigation. The system is intended for authorized network monitoring and security assessment.
The Alert and Notification Module provides information about events or conditions that require user attention. Alerts can be associated with compliance issues, network-related observations, or other monitored activities. By presenting important events through a centralized interface, the system helps users identify potential issues more quickly and reduces the possibility of important information being overlooked during manual monitoring.
The Activity Logging Module maintains records of important actions performed within the application. These records support monitoring, accountability, and traceability of system activities. Maintaining an activity history allows authorized users to review relevant operations and provides useful information when investigating changes or events within the system.
The Analytics and Reporting functionality provides a structured representation of system information through dashboards, tables, and reports. Users can obtain an overview of product records, traceability activities, compliance information, network observations, alerts, and other operational data. This centralized presentation supports easier interpretation of system information and assists users in making informed decisions based on the available records.
The system also incorporates AI-assisted functionality to support the interpretation and handling of information available within Sentinel-Trace. The AI component is designed to assist users by providing relevant explanations, summaries, and guidance based on system information. This reduces the effort required to manually interpret large amounts of operational or monitoring information and provides an additional layer of assistance for users working with the system.
Security is an important aspect of Sentinel-Trace. JWT-based authentication is used to manage authenticated access to protected application resources, while role-based access control helps restrict administrative and sensitive functionality to authorized users. The system also maintains structured activity records to improve accountability. Database access is managed through the application backend, helping separate frontend interaction from direct database operations and providing controlled access to stored information.
The Phase 2 implementation also improves the overall user interface and interaction experience of Sentinel-Trace. The system provides a centralized dashboard, organized navigation, structured forms, tables, status indicators, alerts, and visual representations of important information. The interface is designed to make traceability, compliance, and security monitoring easier to understand and operate. Responsive design principles are applied so that the major system functions can be accessed through different screen sizes.
The database component of the system provides centralized storage for important entities such as users, products, suppliers, production or tracking batches, compliance records, network scan information, security events, alerts, activity logs, and related system records. Structured database management improves data consistency and allows information generated by different modules to be retrieved and displayed when required. The database also provides the foundation for analytics, reporting, traceability, and monitoring functions.
Software testing is carried out in Phase 2 to verify the functionality and integration of the major Sentinel-Trace modules. Individual operations such as user authentication, product management, traceability processing, compliance monitoring, network scanning, alert generation, activity logging, dashboard operations, and report generation are tested by comparing expected results with actual results. Integration testing is also performed to verify communication between the React.js frontend, Flask backend, database, and security-related processing components.
The testing process helps identify errors and inconsistencies within the application and provides an opportunity to improve the reliability and usability of the implemented system. The interaction between the frontend interface, REST API services, backend processing, and database is verified to ensure that information is correctly submitted, processed, stored, retrieved, and displayed. The major modules are evaluated individually as well as as part of the integrated Sentinel-Trace application.
Overall, the Phase 2 version of Sentinel-Trace provides an integrated digital solution for product traceability, compliance monitoring, and network security management. By combining centralized data management, traceability operations, compliance monitoring, network scanning, security alerts, activity logging, analytics, reporting, and AI-assisted functionality, the system reduces manual effort and improves the visibility of important organizational information. The Phase 2 implementation establishes a stronger foundation for future improvements such as advanced predictive analytics, enhanced AI-based anomaly detection, expanded compliance frameworks, improved network security analysis, real-time monitoring, cloud-based deployment, mobile accessibility, and integration with additional enterprise systems.

Traditional methods of maintaining product records, monitoring compliance information, and identifying network-related issues often involve multiple tools and manual processes, which can make information difficult to manage and analyze efficiently.
With the rapid advancement of Artificial Intelligence, web technologies, automation, and network security tools, intelligent systems can be developed to simplify the management and monitoring of complex digital environments. Automated data processing, network scanning, security event monitoring, and AI-assisted analysis can help organizations identify important information more efficiently. By combining product traceability with compliance monitoring and network security capabilities, a centralized system can provide better visibility into both operational and technical activities.
The Sentinel-Trace system is a web-based intelligent platform developed to provide centralized product traceability, compliance monitoring, AI-assisted analysis, and network security monitoring. The system extends the initial Phase 1 design by moving toward a more integrated and implementation-oriented application. Instead of maintaining product information, compliance records, security information, and monitoring activities separately, the proposed system provides a unified environment through which users can manage, monitor, analyze, and retrieve important information from a centralized platform.

2.1 Existing System
The existing system used for managing industrial product information, compliance activities, and network monitoring is primarily based on separate departmental systems and manual record-keeping methods. Product and production information may be maintained using spreadsheets, paper-based records, or independent applications, while network monitoring and security activities may be performed separately. Although these methods can support individual activities, they become increasingly difficult to manage as the amount of operational information increases.
In the manual system, product information is generally recorded at different stages of the product lifecycle. Supplier details, raw material information, production records, quality information, storage details, and distribution information may be maintained separately. When users need to trace a product, they may have to check multiple records or contact different departments to obtain the required information.
The process of tracking products becomes more difficult when a large number of products and production batches are involved. Users may need to search through multiple files or records to identify the source of raw materials, production details, compliance information, or other lifecycle information. This manual process can be time-consuming and may result in incomplete or delayed traceability information.
The existing system also provides limited integration between product management and compliance monitoring. Compliance documents and verification records may be maintained separately from product and production information. As a result, obtaining a complete view of a product's compliance status can require checking multiple sources of information.
Network monitoring is another major limitation of the existing approach. Network devices, services, and security-related information may be monitored using separate tools or manual procedures. Without a centralized system, administrators may find it difficult to obtain an organized view of network activity and identify important security events quickly.
The existing system also provides limited support for centralized reporting and analysis. Product lifecycle information, compliance records, and network security information may exist in different locations, making it difficult to generate comprehensive reports or obtain meaningful insights from the collected data.
Furthermore, traditional industrial management methods provide limited automation for processing and monitoring large amounts of information. Tasks such as maintaining product records, checking compliance information, tracking production activities, monitoring network devices, and identifying security-related events may require significant manual effort. This increases the workload for users and can reduce the efficiency of industrial operations.
Security and access control can also be concerns when operational information is maintained through loosely organized storage methods. Without proper authentication and controlled access, unauthorized users may gain access to sensitive product, compliance, or network information. Separate systems may also lack a centralized mechanism for maintaining user activity and administrative operations.
Overall, the existing industrial management and monitoring approach is fragmented, manual, time-consuming, and inefficient when handling large amounts of operational information. It lacks integrated product traceability, centralized compliance monitoring, unified network security monitoring, organized reporting, and a common platform for managing related industrial information. These limitations make the existing approach less suitable for providing efficient, centralized, and reliable monitoring of modern industrial operations.

The application follows a web-based architecture where the HTML, CSS, and JavaScript frontend communicates with the Flask backend through web-based API services. The backend handles application logic, user access, database operations, product management, compliance monitoring, network scanning, and security-related processing.
The system is designed with a simple and organized interface that includes user authentication, dashboards, product management, supplier and raw material management, production batch management, compliance monitoring, network scanning, network security monitoring, alerts, reports, and administrative controls.
This chapter presents the major design components of the system, including Form Design, Input Design, Output Design, Database Design, and System Development.
3.1 Form Design
Form design provides the interface through which users interact with the Sentinel-Trace system. The forms are designed to be simple, clear, and easy to use, reducing input errors and improving the overall user experience.
The system includes forms for user authentication, supplier registration, raw material entry, product information, production batch details, compliance documentation, network scan requests, and administrative operations. Each form contains clearly labeled fields, buttons, navigation controls, and suitable feedback messages.
Input validation is performed before submitting information to ensure that required fields are completed correctly. Appropriate validation and feedback help users identify incorrect or incomplete information before it is processed by the system.
The forms are developed using HTML, CSS, and JavaScript with an organized web-based layout. Submitted information is sent to the Flask backend, where it is processed and stored using Firebase Firestore through the Firebase Admin SDK.
The form design therefore provides a simple, organized, and reliable interface for product management, compliance monitoring, network monitoring, and administrative activities.
3.2 Input Design
Input design focuses on collecting and validating the information required by the system. Proper input design ensures that accurate and complete data is provided for processing and storage.
The system accepts inputs such as user information, supplier details, raw material information, product details, production batch information, compliance records, and network scan requests. Suitable input fields and controls are provided based on the type of information being entered.
Validation is performed before processing the submitted information. Required fields are checked, invalid or incomplete inputs are identified, and suitable messages are displayed to help users correct errors. Network scan inputs are processed by the backend and passed to the network scanning functionality where required.
The validated information is processed through the Flask backend and stored in Firebase Firestore. The Firebase Admin SDK provides the required server-side communication for storing and retrieving application information.
Overall, the input design provides a simple and reliable method for collecting product, supplier, production, compliance, and network-related information while maintaining data consistency and organized system operation.
3.3 Output Design
Output design focuses on presenting the processed information in a clear and user-friendly manner. The Sentinel-Trace system provides outputs based on product traceability, compliance monitoring, network scanning, security monitoring, and administrative operations.
The main outputs include product traceability information, production batch details, supplier information, compliance records, network scan results, network device information, security alerts, dashboards, reports, and administrative information.
Product-related information is presented in an organized format so that users can understand the lifecycle and current status of products. Compliance information is displayed to support monitoring and verification, while network scanning results provide information about monitored devices, ports, and services.
The system also provides feedback messages for successful operations, validation errors, authentication activities, data updates, network scanning operations, and other system activities. Administrative users can view and manage relevant information through the administrative interface.
The HTML, CSS, and JavaScript frontend receives processed information from the Flask backend and presents it through organized web pages, tables, dashboards, and status displays. The output design therefore provides clear, structured, and easily accessible information for users and administrators.
3.4 Database Design
Database design defines how the system stores, organizes, and manages its information. The Sentinel-Trace system uses Firebase Firestore for storing application data.
The database stores important information such as users, suppliers, raw materials, products, production batches, compliance records, network devices, network scan information, security events, alerts, activity records, and other application data. The Firebase Admin SDK provides communication between the Flask backend and Firebase Firestore for database operations.
The database supports user management, product traceability, supplier and raw material management, production tracking, compliance monitoring, network monitoring, security-related operations, and administrative functions. The centralized database structure allows different modules of the system to access the information required for their operations.
Overall, Firebase Firestore provides a centralized and flexible environment for storing and retrieving the information required by the different components of the Sentinel-Trace system.
3.5 System Development
System development involves converting the designed system into a functional application. The Sentinel-Trace system is developed using HTML, CSS, JavaScript, Python, Flask, Firebase Firestore, Firebase Admin SDK, and Nmap.
The system is developed using a modular approach. The major functions include User Authentication, Dashboard, Product Traceability, Supplier Management, Raw Material Management, Production Batch Management, Compliance Monitoring, Network Scanning, Network Security Monitoring, Alerts and Notifications, Data Visualization, Report Generation, Activity Logging, and Administrative Management.
The Product Traceability module manages product lifecycle information, while the Supplier and Raw Material modules maintain information related to material sources. The Production Batch module maintains production-related records, and the Compliance Monitoring module manages compliance information and documentation.
The Network Scanning module uses Nmap to identify network devices, ports, and available services. The collected information is processed by the backend and presented through the network monitoring interface. The Network Security Monitoring and Alert modules help users review relevant network information and identify events that may require attention.
The frontend is developed using HTML, CSS, and JavaScript, providing the application's forms, dashboards, tables, navigation, and interactive elements. Python and Flask handle backend processing, application logic, API services, and communication with Firebase. Firebase Firestore provides centralized data storage, while the Firebase Admin SDK supports server-side database operations.
Overall, the system development integrates the major modules into a centralized platform that provides an organized solution for product traceability, compliance monitoring, and network security management. The modular design makes the system easier to maintain and provides a foundation for future enhancements and additional industrial monitoring capabilities.

A. Data Flow Diagram
A Data Flow Diagram (DFD) is a graphical representation of the movement of data within a system. It illustrates how information enters the system, how it is processed through different functional modules, where it is stored, and how the processed information is provided as output. DFDs help in understanding the logical flow of data without focusing on programming or implementation details. They are commonly used during the system analysis and design phase to clearly represent the interaction between users, processes, and data stores.
The Sentinel-Trace Product Traceability, Compliance Monitoring, and Network Security Management System uses Data Flow Diagrams to represent the movement of user information, supplier details, raw material information, product details, production batch information, compliance records, network scanning information, security events, alerts, and reports throughout the application. The diagrams illustrate how Users and Administrators interact with the different functional modules and how information is processed and stored within the Firebase Firestore database.
The DFD represents important processes such as user authentication, product management, supplier management, raw material management, production batch management, compliance monitoring, network scanning, network security monitoring, alert management, report generation, and administrative management. When users enter product, supplier, raw material, production, or compliance information, the system processes the information through the Flask backend and stores the required records in Firebase Firestore.
For network monitoring, the user or administrator provides the required network scanning request through the system interface. The Flask backend communicates with Nmap to perform the network scan. The scanning results, including identified network devices, ports, and services, are processed by the system and presented through the application interface. Relevant network information can also be maintained for further monitoring and review.
The DFD is divided into different levels to progressively describe the functionality and data movement of the application. The Context Level DFD provides a high-level view of the complete system and shows the interaction between users, administrators, and the Sentinel-Trace system. The Level 1 DFD further divides the system into major processes such as authentication, product traceability, supplier and material management, production management, compliance monitoring, network scanning, security monitoring, and administration. Further levels can be used to describe individual processes in greater detail where required.
The major data stores represented in the DFD include User Data, Supplier Data, Raw Material Data, Product Data, Production Batch Data, Compliance Data, Network Scan Data, Security Event Data, Alert Data, and Activity Log Data. These data stores are maintained using Firebase Firestore and support the different operations performed by the system.
The overall data flow demonstrates how user and administrator inputs are transformed through the different processing modules into useful outputs such as product traceability information, production records, compliance information, network scan results, security alerts, dashboards, and reports.
Thus, the Data Flow Diagram provides a clear logical representation of how information moves through the Sentinel-Trace Product Traceability, Compliance Monitoring, and Network Security Management System, from user or administrator input to processing, storage, monitoring, and final system output.

APPENDIX C – SAMPLE CODING
The Sentinel-Trace Product Traceability, Compliance Monitoring, and Network Security Management System has been developed using HTML, CSS, and JavaScript for frontend development and Python with Flask for backend processing. Firebase Firestore is used for database management, while the Firebase Admin SDK provides server-side communication between the Flask backend and Firebase services. Nmap is used for network scanning and network information collection.
The application follows a modular architecture, where each module is responsible for a specific functionality such as user authentication, dashboard management, product traceability, supplier management, raw material management, production batch management, compliance monitoring, network scanning, network security monitoring, alerts, reporting, and administrative management.
The following code sections represent selected portions of the important modules implemented in the application. Only selected portions of the source code are included to demonstrate the core functionality of the system. The complete source code is maintained separately as part of the project files.
C.1 User Authentication
This module handles the authentication process required to access the Sentinel-Trace system. It verifies the user credentials submitted through the application and provides access to the appropriate system functions based on the authenticated user's access level.
The Flask backend receives the authentication request from the frontend and communicates with the Firebase services to verify the required user information. Successful authentication allows the user to access protected application features.
